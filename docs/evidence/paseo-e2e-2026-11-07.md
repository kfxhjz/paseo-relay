# Paseo relay transport E2E evidence — 2026-11-07

**English** | [简体中文](../zh-CN/evidence/paseo-e2e-2026-11-07.md)

This is a snapshot of the compatibility run used for the v0.1.0 claim. It is a
local run; the scheduled/manual `Paseo compatibility` workflow reproduces the
same command against a pinned Paseo commit.

## Environment

- Relay: Rust `0.1.0`, release build, single node, plaintext loopback.
- Paseo: commit `ea30d2616a6ea1ad51447cde6e2fc6da4904fe21` (v0.15.3); also
  reproduced against `f21699a37a3d49e8c61bd6d8b65f8a7070f0470c`.
- Node `26.13.0`, vitest `4.1.7`, macOS arm64.
- Test: `packages/server/src/server/daemon-e2e/relay-transport.e2e.test.ts`
  with `PASEO_RELAY_E2E_PORT=<relay port>` and `FORCE_RELAY_E2E=1`.

## Commands

```sh
# Paseo checkout with dependencies installed and workspace dist builds:
#   @getpaseo/{protocol,relay,client,highlight,plugin}
PASEO_RELAY_HOST=127.0.0.1 PASEO_RELAY_PORT=14431 PASEO_RELAY_LOG=debug \
  ./target/release/paseo-relay
PASEO_RELAY_E2E_PORT=14431 FORCE_RELAY_E2E=1 \
  npx vitest run packages/server/src/server/daemon-e2e/relay-transport.e2e.test.ts \
  --maxWorkers=1
```

## Result

```
Test Files  1 passed (1)
     Tests  9 passed | 2 skipped (11)
  Duration  29.18s
```

Relay log: zero WARN/ERROR lines. Two earlier runs produced identical
`9 passed | 2 skipped | 0 failed` results (27.9 s / 31.1 s).

Exercised: v2 control sync/connected/disconnected, generated `conn_` IDs, data
socket attachment, large application transfers (chunked; not single relay
frames), protected E2EE negotiation, rejection of
a legacy client by a protected daemon, 12 s idle without a handshake-timeout
loop, pipelined app hello, byte-for-byte file reads, relay ping/pong, and
SIGTERM drain/restart.

Skipped by the test file in external-relay mode (not relay failures):

- connected-hosts RPC/binary traffic across a relay restart (a local
  development experiment, not committed, exercised the reconnect/RPC path);
- invalid-handshake-key close-code assertion (the relay rejects the key itself
  with `1008`, which the test file documents as the Elixir relay behavior).

A separate manual wire probe during development covered v1 forwarding and
replacement, v2 control/data, handshake rejection, and close codes. The probe
script/transcript is not committed; this is supplementary evidence, while the
reproducible evidence is the official E2E result above.

## Reproduce

Use [scripts/compat-paseo.sh](https://github.com/kfxhjz/paseo-relay/blob/main/scripts/compat-paseo.sh) or the
`Paseo compatibility` GitHub workflow. Both pin the Paseo commit. Environments
without Node/Paseo network access can still run `cargo test` and the protocol
integration tests.
