# Paseo relay 传输 E2E 证据 — 2026-11-07

[English](../../evidence/paseo-e2e-2026-11-07.md) | **简体中文**

这是 v0.1.0 兼容性声明的运行快照。它是本地运行；计划/手动的
`Paseo compatibility` 工作流会用固定 Paseo commit 复现同一命令。

## 环境

- Relay：Rust `0.1.0`，release 构建，单节点，明文 loopback。
- Paseo：commit `ea30d2616a6ea1ad51447cde6e2fc6da4904fe21`（v0.15.3）；也在
  `f21699a37a3d49e8c61bd6d8b65f8a7070f0470c` 上复现。
- Node `26.13.0`，vitest `4.1.7`，macOS arm64。
- 测试：`packages/server/src/server/daemon-e2e/relay-transport.e2e.test.ts`，
  使用 `PASEO_RELAY_E2E_PORT=<relay port>` 和 `FORCE_RELAY_E2E=1`。

## 命令

```sh
# Paseo checkout 已安装依赖并构建 workspace dist：
#   @getpaseo/{protocol,relay,client,highlight,plugin}
PASEO_RELAY_HOST=127.0.0.1 PASEO_RELAY_PORT=14431 PASEO_RELAY_LOG=debug \
  ./target/release/paseo-relay
PASEO_RELAY_E2E_PORT=14431 FORCE_RELAY_E2E=1 \
  npx vitest run packages/server/src/server/daemon-e2e/relay-transport.e2e.test.ts \
  --maxWorkers=1
```

## 结果

```

```

Relay 日志：0 WARN/ERROR。更早两次运行结果一致：
`9 passed | 2 skipped | 0 failed`（27.9 s / 31.1 s）。

覆盖：v2 control sync/connected/disconnected、生成的 `conn_` ID、data socket attach、
大应用传输（分块，不是单条 relay 帧）、protected E2EE 协商、protected daemon 拒绝 legacy client、12 秒 idle
不进入 handshake-timeout loop、pipelined app hello、byte-for-byte 文件读取、relay
ping/pong、SIGTERM drain/restart。

external-relay 模式下被测试文件跳过（不是 relay 失败）：

- relay 重启后的 connected-hosts RPC/binary 流量（开发期本地实验、未提交，跑过
  reconnect/RPC 路径）；
- 非法 handshake key 的 close-code 断言（relay 自己以 `1008` 拒绝 key，测试文件也
  说明 Elixir relay 是同样行为）。

开发期另做过手动 wire probe，覆盖 v1 转发/替换、v2 control/data、handshake 拒绝
和 close code；probe 脚本/输出未提交，是补充材料；可复现证据是上面的官方 E2E 结果。

## 复现

使用 [scripts/compat-paseo.sh](https://github.com/kfxhjz/paseo-relay/blob/main/scripts/compat-paseo.sh) 或

访问的环境仍可运行 `cargo test` 和协议集成测试。
